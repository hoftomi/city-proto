# Trón nélkül – mobile client

Flutter 3.47 (Dart 3.13), Android and iOS. The visuals follow the Krónika IV design system (see `tools/k4_export`).

## Architecture

From top to bottom, each layer only knows the one below it:

```
widget  →  bloc  →  service  →  repository  →  datasource  →  (Dio / Firebase / secure storage)
```

| Layer | Where | Responsibility |
|---|---|---|
| datasource | `lib/data/datasource/` | Thin wrappers around external systems: the generated API client (`remote/`), the Firebase, Google, Apple and Discord SDKs (`auth/`), secure storage (`local/`). Throws an exception on error. |
| repository | `lib/data/repository/` | Combines the data sources and returns `Either<Failure, T>` (either_dart). Exceptions become a `Failure` carrying the ProblemDetail `detail` field. Caches the maps. |
| service | `lib/domain/service/` | Business and derived logic: the game clock, due refreshes, the newly added order, form validation, request assembly. Helpers for the generated models live in `lib/domain/model/` (extensions). |
| bloc | `lib/ui/<screen>/bloc/` | The state. Events are `sealed class … extends Equatable`, the state is `Equatable` and only changes through `copyWith` (following the ktk pattern, in `part` files). One-off messages go through a sequence-numbered `Notice` field. |
| widget | `lib/ui/<screen>/`, `lib/widgets/` | Only renders and dispatches events. `lib/widgets` holds the purely presentational design system components. |

- **Dependencies:** get_it and injectable, `lib/app/di/`. Registration is generated by build_runner (`di.config.dart`).
- **Navigation:** go_router, `lib/app/router/`. Redirects follow the `AuthBloc` state. The game's five tabs are branches of a `StatefulShellRoute` (`/games/:id/play/{map,city,reports,orders,ranking}`), and the city and district of the city view are query parameters, so they are deep-linkable. The `GameBloc` spans the whole game.
- **API:** Dio; the `AuthInterceptor` attaches the Firebase ID token. On 401 `SessionEvents` signals, and the `AuthBloc` signs the user out.

## UI text

All UI text comes from the backend. Its source is in the `tron-nelkul/backend/src/main/resources/i18n/<language>/<namespace>.json` files, and the server serves it at the `GET /api/i18n/{lang}` endpoint.

- **Loading:** the mobile app uses easy_localization, with `TranslationRepository` as the loader. It first takes the server's fresh version (and saves it); if that is unavailable, the last saved one; finally the app's fallback (`assets/translations`).
- **Syncing:** the fallback is produced from the backend files by `python3 tools/sync_translations.py`. Do not edit it by hand.
- **Text in code:** blocs and services do not emit finished text but a `Tr` (a translation key and parameters, or ready-made text from the server). The widget displays `.text` or `'key'.tr()`.
- **Key test:** `test/l10n` checks that every key used in the code exists and that the fallback is up to date.

## Code generation

```bash
FLUTTER=/path/to/flutter tools/generate_api.sh   # API client and models from ../tron-nelkul/backend/openapi.yaml → packages/tron_api
dart run build_runner build                      # DI (injectable)
```

For the API contract, see [`../api/README.md`](../api/README.md).

## Tests

```bash
flutter test
```

- **Blocs:** bloc_test and mocktail, with mocked services or repositories (`test/ui/`).
- **Contract:** the backend's real responses can be parsed with the generated models (`test/contract/`, samples: `test/fixtures/`).
